# Document Search API

Простой поисковик по текстам документов. Данные хранятся в PostgreSQL, поисковый индекс в Elasticsearch. Сервис асинхронный и полностью работает в Docker.

## Возможности

- полнотекстовый поиск по тексту документов (русская морфология);
- удаление документа из БД и из поискового индекса по `id`;
- автоматическая загрузка тестового набора данных `posts.csv` при первом запуске;
- документация API в формате OpenAPI (`docs.json`).

## Стек

- Python 3.12, FastAPI, Uvicorn
- SQLAlchemy 2 (async) + asyncpg, PostgreSQL 17
- Elasticsearch 9 (async-клиент)
- Docker, Docker Compose

## Быстрый старт

Нужны только **Docker** и **Docker Compose**.

1. Клонируйте репозиторий и перейдите в его папку.

2. Создайте файл с настройками из примера:

   ```bash
   # Linux / macOS
   cp .env.example .env

   # Windows (PowerShell)
   copy .env.example .env
   ```

3. Откройте `.env` и задайте пароль базы данных в `DB_PASS` (значение `CHANGE_ME` заменить на свой пароль).

4. Соберите и запустите сервис в фоне:

   ```bash
   docker compose up --build -d
   ```

   Первый запуск занимает до минуты: Elasticsearch стартует медленно, а сервис дожидается его готовности. При первом старте создаются таблица и индекс, затем в них загружаются документы из `posts.csv`.

5. Проверьте, что всё поднялось:

   ```bash
   docker compose ps          # у всех сервисов статус healthy
   docker compose logs -f backend   # логи сервиса (выход: Ctrl+C)
   ```

   Когда у `backend` появится статус `healthy` (в логах `Application startup complete`), сервис доступен:

   | Что | Адрес |
   |---|---|
   | API | http://localhost:8000 |
   | Swagger UI | http://localhost:8000/docs |
   | ReDoc | http://localhost:8000/redoc |
   | OpenAPI-схема | http://localhost:8000/openapi.json |

   Порт можно изменить через `APP_PORT` в `.env`.

### Остановка и сброс

```bash
docker compose down        # остановить, данные сохраняются
docker compose down -v     # остановить и удалить все данные (БД и индекс)
```

После `down -v` при следующем запуске данные из `posts.csv` загрузятся заново.

## Настройки (`.env`)

| Переменная | Описание | Пример |
|---|---|---|
| `DB_HOST` | хост PostgreSQL (внутри Docker всегда `database`) | `database` |
| `DB_PORT` | порт PostgreSQL | `5432` |
| `DB_USER` | пользователь БД | `postgres` |
| `DB_PASS` | пароль БД (**обязательно задать**) | — |
| `DB_NAME` | имя БД | `postgres` |
| `ELASTICSEARCH_HOST` | адрес Elasticsearch | `http://elasticsearch:9200` |
| `APP_PORT` | порт сервиса на хосте | `8000` |

Файл `.env` содержит секреты и не должен попадать в git (он добавлен в `.gitignore`).

## API

### Поиск документов

`GET /search?query=<текст>`

Принимает произвольный текстовый запрос, ищет по тексту документов в индексе и возвращает до 20 документов со всеми полями БД.

Пример ответа:

```json
[
  {
    "id": 1,
    "text": "Текст документа...",
    "rubrics": ["VK-1603736028819866", "VK-11879320040"],
    "created_date": "2019-07-25T12:42:13"
  }
]
```

Как формируется результат:

1. Elasticsearch выбирает 20 самых релевантных документов.
2. Полные данные этих документов берутся из PostgreSQL.
3. Результат сортируется по `created_date` по убыванию (новые первыми).

Если ничего не найдено, возвращается пустой список. Пустой запрос приводит к ошибке `422`.

### Удаление документа

`DELETE /documents/{document_id}`

Удаляет документ из БД и из поискового индекса по `id` (целое число от 1 до 2147483647).


| Код | Значение |
|---|---|
| `204` | документ удалён, тело ответа пустое |
| `404` | документ с таким `id` не найден |
| `422` | некорректный `id` |

Повторное удаление того же документа вернёт `404`.

## Как это устроено

При старте сервис по порядку:

1. создаёт таблицу `documents` в PostgreSQL, если её нет;
2. создаёт индекс `documents` в Elasticsearch, если его нет;
3. если таблица пуста, загружает документы из `posts.csv` в БД и в индекс.

**Структура БД** (таблица `documents`):

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | уникальный идентификатор |
| `rubrics` | text[] | массив рубрик |
| `text` | text | текст документа |
| `created_date` | timestamp | дата создания |

**Структура индекса** (`documents`):

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | `id` из базы (он же `_id` документа в индексе) |
| `text` | text | текст документа, анализатор `russian` |

Анализатор `russian` приводит слова к основе, поэтому запрос «документы» найдёт и «документ».

## Документация OpenAPI

Актуальная схема лежит в файле [`docs.json`](docs.json). Если вы изменили эндпоинты, обновите её, запустив сервис и скачав схему заново:

```bash
curl -o docs.json http://localhost:8000/openapi.json
```

(в PowerShell используйте `curl.exe`). Не забудьте пересобрать контейнер после изменений кода: `docker compose up --build -d`.

## Тесты

Функциональные тесты отправляют HTTP-запросы в **уже запущенный** сервис, поэтому сначала поднимите его (`docker compose up --build -d`).

Запустите тесты из корня проекта:

```bash
   pytest -v
```

По умолчанию тесты обращаются к `http://localhost:8000`. Если сервис работает на другом адресе, измените переменную BASE_URL в test_api:

Тесты проверяют поиск (лимит 20 документов, сортировку по дате, наличие всех полей, пустой результат, валидацию запроса) и удаление (успешное удаление, повторное удаление, несуществующий и некорректный `id`).

> **Важно:** тесты на удаление реально удаляют документы (по 2 за запуск). Чтобы вернуть данные, выполните `docker compose down -v`, затем `docker compose up --build -d`.
